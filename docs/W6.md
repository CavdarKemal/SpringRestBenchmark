# W6 — Postgres COPY (nativer Bulk-Load)

> **Track:** Write · **Vorgänger:** [W5](W5.md) / [W4](W4.md) · **Nachfolger:** [W7](W7.md)

## Konzept

Alle bisherigen Stufen benutzen `INSERT` — und selbst der schnellste INSERT-Weg (W4) muss
jede Zeile durch den regulären Anfrage-Pfad der Datenbank schleusen (Parsen, Planen,
Ausführen). PostgreSQL hat für Massendaten ein **eigenes Protokoll**: `COPY ... FROM STDIN`.
Es überträgt die Zeilen als Datenstrom und schreibt sie auf dem kürzesten Weg in die
Tabelle. Das ist der **schnellste** Weg, große Datenmengen zu laden.

Wir sprechen COPY direkt über den pgjdbc-`CopyManager` an.

## Code-Walkthrough

- `service/WriteService.java` → `w6Copy(...)`:
  1. holt eine `Connection` aus der DataSource,
  2. entpackt sie zu `PGConnection` (`connection.unwrap(PGConnection.class)`),
  3. baut mit `toCsv(...)` einen CSV-Text und übergibt ihn an
     `copyManager.copyIn("COPY measurements (...) FROM STDIN WITH (FORMAT csv)", reader)`.
- `toCsv(...)`: erzeugt pro Zeile eine CSV-Zeile. Unsere Daten enthalten keine
  Sonderzeichen (Kategorie aus fester Liste, Payload nur Kleinbuchstaben), daher ist **kein
  CSV-Escaping** nötig. Ein **leeres** Feld bedeutet im CSV-Modus `NULL` — genau richtig für
  ein fehlendes `payload` (dafür gibt es einen eigenen Test).

## Fallstricke & Trade-offs

- **Escaping:** Bei echten Daten mit Kommas, Anführungszeichen oder Zeilenumbrüchen **muss**
  man CSV korrekt escapen (oder das Text-/Binärformat von COPY nutzen). Unsere Vereinfachung
  gilt nur, weil die Testdaten kontrolliert sind.
- **NULL vs. leerer String:** Im CSV-Modus ist ein *unquotetes* leeres Feld `NULL`, ein
  *quotetes* `""` der leere String. Diese Feinheit ist eine typische Fehlerquelle.
- COPY umgeht Trigger-freundliche Einzelverarbeitung — es ist für reinen Bulk-Load gedacht.

## Ausblick

- **[W7](W7.md)** verlässt die „eine Verbindung, seriell"-Welt: Es verteilt den Ingest über
  **mehrere Verbindungen parallel** (Virtual Threads) — und hier wird endlich die
  **Größe des Connection-Pools** (HikariCP) zum entscheidenden Faktor.
