# R2 — Pagination: Offset vs. Keyset

> **Track:** Read · **Vorgänger:** [R1](R1.md) · **Nachfolger:** [R3](R3.md)

## Konzept

R0/R1 laden **alles auf einmal**. R2 holt die Daten stattdessen **seitenweise**. Dabei gibt
es zwei grundverschiedene Techniken:

**Offset-Pagination** (`ORDER BY id OFFSET ? LIMIT ?`):
Die DB sortiert, **überspringt** `OFFSET` Zeilen und liefert die nächsten `LIMIT`. Das
Überspringen bedeutet: Für Seite *n* muss die DB *n × Seitengröße* Zeilen durchlaufen —
tiefe Seiten werden **immer langsamer**.

**Keyset-Pagination / Seek** (`WHERE id > ? ORDER BY id LIMIT ?`):
Statt zu überspringen, **springt** die DB per Index direkt hinter den zuletzt gesehenen
Schlüssel. Jede Seite kostet gleich viel — **unabhängig von der Tiefe**.

## Was die Messung zeigt

100 000 Zeilen, eine **tiefe** Seite (Position ~95 000, Größe 5000):

| Technik | Zeit für die tiefe Seite |
|---------|--------------------------|
| Offset (`OFFSET 95000`) | ~0,208 s |
| **Keyset (`WHERE id > 95000`)** | **~0,062 s** |

Keyset ist hier ~3,4× schneller — und der Abstand **wächst** mit der Seitentiefe. Traversiert
man die **ganze** Tabelle Seite für Seite (im Dashboard), summiert sich der Offset-Nachteil
deutlich auf.

## Code-Walkthrough

- `service/ReadService.java` → `pageByOffset(...)` / `pageByKeyset(...)`: dieselbe Projektion,
  nur die WHERE-/OFFSET-Klausel unterscheidet sich.
- `controller/ReadController.java` → `/r2/offset` und `/r2/keyset`.
- Client (`stages.ts`, `traverseOffset` / `traverseKeyset`): blättert die ganze Tabelle
  durch und misst die Gesamtzeit. Keyset merkt sich die **letzte id** als nächsten `afterId`.

## Fallstricke & Trade-offs

- **Keyset kann nicht direkt auf Seite *n* springen** — es kennt nur „weiter ab hier". Für
  „Springe zu Seite 500" ist Offset nötig (oder eine andere Strategie). Das ist der zentrale
  Trade-off: Keyset ist schneller, aber weniger flexibel.
- Keyset braucht eine **eindeutige, indizierte Sortierspalte** (hier `id`). Bei Sortierung
  nach nicht-eindeutigen Spalten muss man den Schlüssel zusammensetzen (z. B. `(ts, id)`).
- Offset ist einfacher und für **flache** Seiten (die ersten paar) völlig in Ordnung.

## Ausblick

- **[R3](R3.md)** löst ein anderes Problem: nicht *wie viel*, sondern *wann* die Daten
  ankommen — Streaming senkt die Time-To-First-Byte.
